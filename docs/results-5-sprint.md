# Отчёт по Спринту 5: Автоматическая синхронизация 3-нодовой сети, восстановление после сбоев и Web UI

## 1. Цель спринта

Научить независимые ноды сети `blockchain_logistics` автоматически обмениваться новыми блоками, отслеживать своё отставание, восстанавливать актуальное состояние блокчейна после временного отключения (включая догоняющую синхронизацию на несколько блоков без повреждения локальной цепочки), а также обеспечить полноценный рабочий Web UI, отражающий реальное состояние сети, блоков и ошибок.

---

## 2. Итоги спринта: что реализовано

### Выполнение требований спринта

* [x] **Работа с сетью из 3 независимых нод:** система протестирована и настроена для одновременного запуска 3 узлов (`node-1:8001`, `node-2:8002`, `node-3:8003`) локально без Docker, с изолированными файлами цепочек и пиров.
* [x] **Постоянное хранение известных нод сети:** список пиров каждой ноды атомарно сохраняется на диск (`data/<node_id>_peers.json`) и автоматически загружается при перезапуске с объединением с параметрами запуска (`--peers` / `NODE_PEERS`).
* [x] **Гибридная синхронизация (Auto-Push + периодический Pull):**
  * при создании блока (`POST /api/v1/blocks`, теперь `broadcast=true` по умолчанию) нода сразу рассылает его всем известным пирам;
  * в фоне через `lifespan` FastAPI работает цикл периодического опроса пиров (`--sync-interval`, по умолчанию 5 сек) и автоматическая проверка при старте.
* [x] **Определение отставания локальной цепочки:** добавлен эндпоинт `GET /api/v1/peers/status`, который опрашивает всех известных пиров, определяет их доступность (`Online` / `Offline`), совместимость генезиса, точное отставание (`lag`) и флаг `is_behind`.
* [x] **Догоняющая синхронизация на несколько блоков с атомарной защитой:**
  * реализована выборка диапазона блоков `GET /api/v1/blocks?from_index=<N>` и синхронизация `POST /api/v1/sync`;
  * в ядре добавлены `validate_incoming_blocks()` и `receive_blocks()`: если в полученном пакете из нескольких блоков хотя бы один блок или транзакция повреждены/подделаны, **отклоняется весь пакет**, локальная цепочка не повреждается, а нода переключается на честного пира.
* [x] **Восстановление после временного отключения:** остановленная нода после повторного запуска автоматически восстанавливает локальную цепь и список пиров с диска, обнаруживает пропущенные блоки и подтягивает их от активных узлов сети.
* [x] **Рабочий Web UI, отражающий реальное состояние системы:**
  * просмотр всей цепочки блоков, хешей и транзакций;
  * таблица всех узлов сети (включая текущую ноду) со статусами `Online`/`Offline`, высотой цепи и бейджем отставания;
  * форма добавления новых записей и блоков с мгновенной рассылкой;
  * отображение ошибок бэкенда и попыток подмены данных (баннер ошибок + живой журнал событий `GET /api/v1/node/events` с автообновлением каждые 3 сек).
* [x] **Обратная совместимость:** вся функциональность Спринтов 3 и 4 (валидация ядра, ручной Push/Pull, Swagger API, старые автотесты) полностью сохранена и проходит регрессию.

### Ключевые технические изменения

| Компонент | Что добавлено / обновлено |
| :--- | :--- |
| `app/blockchain/chain.py` | Методы `get_blocks_from()`, `validate_incoming_blocks()`, `receive_blocks()` для атомарной проверки и дозаписи пакета блоков |
| `app/core/config.py` | Поля `peers_path`, `sync_interval`, `auto_sync_on_startup`, поддержка переменных окружения `PEERS_PATH`, `NODE_SYNC_INTERVAL`, `NODE_AUTO_SYNC` |

| `app/api/v1/endpoints/nodes.py` | Эндпоинты `GET /api/v1/peers/status`, `POST /api/v1/sync`, `GET/DELETE /api/v1/node/events`, параметр `from_index` для `GET /api/v1/blocks` |

## 3. Распределение ролей и вклад каждого участника (команда из 5 человек)

В 5-м спринте задачи были распределены между 5 участниками команды; ИИ-ассистент выступал в роли инженера-тестировщика (подготовка матрицы тест-кейсов и рекомендаций по проверке отказоустойчивости).

### 1. Аналитик и архитектор (Участник 1)
* **Зона ответственности:** проектирование протокола синхронизации, формализация требований и пользовательских сценариев для 3-нодовой сети и UI.
* **Вклад в спринт:**
  * Спроектировал гибридную схему синхронизации (Auto-Push при создании блока + Startup/Periodic Pull при старте и по таймеру) с сохранением обратной совместимости со Спринтом 4.
  * Определил алгоритм выявления отставания (`height_diff` / `lag` при совпадении `genesis_hash`) и правило атомарного отклонения пакета блоков при обнаружении подмены.
  * Сформулировал пользовательские сценарии для Web UI (мониторинг всех узлов, отображение отставания, просмотр ошибок бэкенда и подмен) и расширил API-контракт новыми эндпоинтами (`/peers/status`, `/sync`, `/node/events`, `?from_index=`).
  * Подготовил итоговую документацию и отчёт по результатам спринта.
* **Артефакты:** спецификация синхронизации, обновлённые требования и отчёт (`docs/sprint5-report.md`).

### 2. Разработчик (Участник 2)
* **Зона ответственности:** реализация логики синхронизации, пакетной валидации в ядре блокчейна, журнала событий и REST API.
* **Вклад в спринт:**
  * Реализовал в `app/blockchain/chain.py` пакетную проверку и атомарное добавление цепочки новых блоков (`get_blocks_from`, `validate_incoming_blocks`, `receive_blocks`).
  * Разработал в `app/services/node_service.py` механизм персистентного хранения пиров, асинхронный опрос сети (`get_peers_status`), догоняющую синхронизацию (`sync_with_peer`, `sync_with_network`) с переключением на честного пира при отказе от скомпрометированного узла, а также потокобезопасный журнал событий и ошибок.
  * Обновил Pydantic-схемы (`app/schemas/node.py`) и контроллеры FastAPI (`app/api/v1/endpoints/nodes.py`), изменил значение по умолчанию `broadcast=True` для автоматического оповещения сети при создании блока.
* **Артефакты:** `app/blockchain/chain.py`, `app/schemas/node.py`, `app/services/node_service.py`, `app/api/v1/endpoints/nodes.py`.

### 3. DevOps-инженер (Участник 3)
* **Зона ответственности:** конфигурация и жизненный цикл нод, запуск кластера из 3 узлов без Docker, изоляция хранилищ и интеграция автоматического прогона тестов.
* **Вклад в спринт:**
  * Реализовал управляемый жизненный цикл фоновых задач через FastAPI `lifespan` (`app/main.py`) для корректного запуска и безопасного завершения цикла синхронизации при остановке ноды (`Ctrl+C`).
  * Расширил систему конфигурации (`app/core/config.py`) и CLI-раннер (`run_node.py`): добавил параметры `--peers-file`, `--sync-interval` и соответствующие переменные окружения (`PEERS_PATH`, `NODE_SYNC_INTERVAL`, `NODE_AUTO_SYNC`).
  * Настроил изолированное файловое хранение блокчейнов и списков пиров для 3+ инстансов в директории `data/` с атомарной перезаписью (`*.tmp` + `os.replace`), чтобы исключить повреждение файлов при аварийном отключении ноды.
  * Подготовил сценарии локального развёртывания 3-нодовой сети и регрессионного прогона `pytest`.
* **Артефакты:** `app/core/config.py`, `app/main.py`, `run_node.py`, раздел запуска в `docs/sprint5-run-and-test.md`.

### 4. UI-разработчик (Участник 4)
* **Зона ответственности:** развитие веб-интерфейса и связывание его со всеми новыми эндпоинтами бэкенда.
* **Вклад в спринт:**
  * Переработал панель управления (`app/static/index.html`) под реальную распределённую сеть: добавил сводную таблицу узлов (текущая нода + все известные пиры) с живыми бейджами `Online`/`Offline`, высотой цепочки и индикатором отставания (*«Мы отстаём на N бл.»*).
  * Подключил автообновление интерфейса каждые 3 секунды (с возможностью отключения) и кнопку принудительной синхронизации всей сети или отдельного пира.
  * Реализовал отображение ошибок бэкенда и попыток подмены данных: всплывающий красный баннер для HTTP-ошибок и обновляемый виджет журнала событий с цветовой градацией (`INFO` / `WARNING` / `ERROR`) и кодами ошибок (`INVALID_BLOCK_HASH`, `INVALID_TRANSACTION_HASH`, `GENESIS_MISMATCH` и др.).
  * Сохранил и улучшил форму создания транзакций/блоков с авто-рассылкой и обозреватель цепочки блоков.
* **Артефакты:** `app/static/index.html`.

### 5. Тестировщик / QA (Участник 5) *(при поддержке ИИ-ассистента в роли QA)*
* **Зона ответственности:** проектирование тест-кейсов, автоматизация сетевых и негативных проверок, тестирование восстановления и регрессия.
* **Вклад в спринт:**
  * Совместно с ИИ-ассистентом составил набор из 12 тест-кейсов (`TC-01`–`TC-12`), охватывающих позитивные, негативные, отказоустойчивые и регрессионные сценарии.
  * Разработал интеграционный тестовый модуль `tests/test_sync.py` на базе кастомного `ClusterTransport`, который поднимает 3 независимые FastAPI-ноды с имитацией отключения (`set_offline`/`set_online`) и перезапуска процесса.
  * Автоматизировал проверку авто-рассылки по 3 нодам, сохранения пиров на диске, определения отставания, догоняющей синхронизации на несколько блоков, фонового цикла опроса, атомарного отклонения скомпрометированного пакета с переключением на честный узел и логирования атак для UI.
  * Провёл ручное сквозное тестирование 3 запущенных нод, проверил отсутствие регрессий по Спринтам 3–4 и описал чек-лист проверок для демонстрации.
* **Артефакты:** `tests/test_sync.py`, `docs/sprint5-test-cases.md`, раздел тестирования в `docs/sprint5-run-and-test.md`.
