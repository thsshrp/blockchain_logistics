# Инструкция по запуску и проверке проекта `blockchain_logistics` (Спринт 4)

Проект запускается локально на Python **без использования Docker**: каждая нода работает как отдельный процесс на своём порту и использует собственный JSON-файл для хранения блокчейна.

---

## 1. Требования к окружению

* **Python 3.10+** (проверено на Python 3.12)
* **pip** (менеджер пакетов Python)
* Два открытых окна терминала (или вкладки в IDE) и браузер

> **Важно:** все команды ниже выполняются из **корневой директории репозитория** (`blockchain_logistics/`), чтобы Python корректно находил пакет `app`.

---

## 2. Установка зависимостей

Рекомендуется создать виртуальное окружение:

### Windows (PowerShell)
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### Windows (CMD)
```cmd
python -m venv .venv
.venv\Scripts\activate.bat
pip install -r requirements.txt
```

### Linux / macOS
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

> **Совет по Git:** добавьте строку `data/` в файл `.gitignore`, чтобы локальные JSON-хранилища запущенных нод не попадали в коммиты.

---

## 3. Запуск автотестов

Перед ручным запуском нод убедитесь, что все модульные тесты ядра и интеграционные сетевые тесты (включая негативные сценарии) проходят успешно:

```bash
pytest -v
```

Что проверяется автоматически:
* `tests/test_crypto.py`, `test_transaction.py`, `test_block.py`, `test_blockchain.py`, `test_storage.py` — криптография, хеширование, структура блоков и сохранение на диск.
* `tests/test_network.py` — запуск двух независимых нод с изолированными хранилищами, совпадение генезис-блока, двусторонняя регистрация, инспекция пира, передача (Push) и запрос (Pull) блоков, а также отклонение поддельных, дублирующихся и несогласованных блоков.

---

## 4. Запуск нескольких независимых нод

Откройте **два терминала** в корне проекта (с активированным виртуальным окружением).

### Терминал 1 — Запуск Ноды 1 (порт `8001`)
```bash
python run_node.py --node-id node-1 --port 8001 --storage data/node1_blockchain.json
```

### Терминал 2 — Запуск Ноды 2 (порт `8002`)
```bash
python run_node.py --node-id node-2 --port 8002 --storage data/node2_blockchain.json
```

*(Опционально)* Вы можете запустить третью и последующие ноды, указав свободный порт и отдельный файл хранилища, а также сразу передать известных пиров через `--peers`:

```bash
python run_node.py --node-id node-3 --port 8003 --storage data/node3_blockchain.json --peers http://127.0.0.1:8001,http://127.0.0.1:8002
```

### Доступные интерфейсы после запуска

| Нода | Web UI (браузер) | Swagger API (OpenAPI) | Файл хранилища |
| :--- | :--- | :--- | :--- |
| **node-1** | `http://127.0.0.1:8001/` | `http://127.0.0.1:8001/docs` | `data/node1_blockchain.json` |
| **node-2** | `http://127.0.0.1:8002/` | `http://127.0.0.1:8002/docs` | `data/node2_blockchain.json` |

## 5. Пошаговая демонстрация работы через Web UI

Откройте в браузере две вкладки рядом: `http://127.0.0.1:8001/` и `http://127.0.0.1:8002/`.

1. **Проверка независимости и общего генезиса**
   * Убедитесь, что у обеих нод разные `node_id` и пути к файлам хранилища, но одинаковый **«Хеш генезиса»**.
2. **Установление связи между нодами**
   * На вкладке **node-1** в блоке *«Сеть и взаимодействие с пирами»* введите `http://127.0.0.1:8002`.
   * Оставьте галочку **«Двусторонняя регистрация (handshake)»** включённой и нажмите **«Подключить»**.
   * Обновите вкладку **node-2** — в списке её пиров автоматически появится `http://127.0.0.1:8001`.
3. **Получение информации о другой ноде**
   * Нажмите кнопку **«Статус»** напротив пира. В *«Журнале операций и ответов сети»* отобразятся высота его цепочки, статус валидности и поле `"compatible_genesis": true`.
4. **Передача нового блока (сценарий Push)**
   * На **node-1** заполните форму *«Создать блок с транзакцией»* (например, `CREATE_SHIPMENT`, `SH-100`, `To User ID = 1`), оставьте галочку **«Сразу разослать блок всем пирам (Push)»** и нажмите **«Добавить блок»**.
   * В журнале появится статус `"accepted"`. Перейдите на вкладку **node-2** и нажмите **«Обновить»** — Блок #1 уже проверен и добавлен в её цепочку и файл `data/node2_blockchain.json`.
5. **Запрос блока другой нодой (сценарий Pull)**
   * На **node-1** снимите галочку **«Сразу разослать блок всем пирам (Push)»** и создайте Блок #2 (например, `TRANSFER_SHIPMENT`, `SH-100`, `From = 1`, `To = 2`).
   * Перейдите на вкладку **node-2** и нажмите **«Запросить блок (Pull)»** напротив `http://127.0.0.1:8001`. Нода 2 сама скачает следующий ожидаемый блок (#2), проверит все хеши и сохранит его у себя.
6. **Проверка целостности и персистентности**
   * Нажмите **«Проверить цепочку»** на обеих нодах.
   * Остановите `node-2` (`Ctrl + C`) и снова запустите ту же команду — все блоки восстановятся из `data/node2_blockchain.json`.

## 6. Проверка негативных сценариев (отклонение некорректных блоков)

Негативные сценарии удобно демонстрировать через Swagger UI (`http://127.0.0.1:8002/docs` → `POST /api/v1/blocks/receive`) или через `curl`:

### Пример: отправка блока с подменённым `prev_hash`
```bash
curl -X POST http://127.0.0.1:8002/api/v1/blocks/receive \
  -H "Content-Type: application/json" \
  -d '{
    "index": 3,
    "timestamp": "2026-10-22T12:00:00+00:00",
    "transactions": [],
    "prev_hash": "fake_prev_hash_000000",
    "hash": "fake_hash_111111",
    "nonce": 0
  }'
```
Ожидаемый ответ — HTTP `409 Conflict` с кодом `PREV_HASH_MISMATCH` (или `INVALID_BLOCK_INDEX`, если текущая длина цепочки не равна `3`). Цепочка ноды при этом не изменяется.

### Другие проверки, которые можно воспроизвести через Swagger
* **Подмена поля транзакции** (изменить `shipment_number`, не меняя `tx.hash`) → `400 Bad Request`, `INVALID_TRANSACTION_HASH`.
* **Подмена хеша блока** (изменить `hash` на любой другой) → `400 Bad Request`, `INVALID_BLOCK_HASH`.
* **Повторная отправка существующего блока** → `409 Conflict`, `DUPLICATE_BLOCK`.
* **Подключение недоступной ноды** (`POST /api/v1/peers/register` с `http://127.0.0.1:9999`) → `502 Bad Gateway`, `PEER_UNREACHABLE`.

## 7. Частые проблемы и их решение

* **`ModuleNotFoundError: No module named 'app'`** — команда запущена не из корневой папки проекта. Перейдите в корень репозитория (`cd blockchain_logistics`).
* **`Address already in use` / порт занят** — выберите другой порт через `--port 8003`.
* **`GENESIS_MISMATCH` при подключении пира** — один из JSON-файлов остался от предыдущей версии (Спринт 3) с другим временем генезис-блока. Удалите старые файлы из папки `data/` и перезапустите ноды.
